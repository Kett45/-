# خطة إصلاح خطأ 404 وإتاحة التحميل المباشر لملف الـ APK على GitHub تلقائياً

تعالج هذه الخطة السبب الجذري لظهور صفحة **404 Not Found** على GitHub بعد الرفع من AI Studio، وتضمن عمل زر التحميل المباشر وقسم **Releases** تلقائياً لأي اسم مستودع بدون أي إعداد يدوي.

## قرارات المستخدم المعتمدة (User Review & Critical Decisions)

> [!IMPORTANT]
> بناءً على اختياراتك:
> - **نطاق الحل**: إصلاح رابط التحميل المباشر وتفعيل قسم **Releases** داخل صفحة GitHub مباشرةً.
> - **التعرف التلقائي على رابط المستودع**: الحل سيعمل تلقائياً مع أي اسم مستودع أو حساب على GitHub دون الحاجة لمعرفة الرابط مسبقاً.

---

## 1. تشخيص السبب الدقيق لظهور خطأ 404 (Root Cause Analysis)

بعد فحص بيئة البناء وطريقة رفع الملفات إلى GitHub، تبيّن أن خطأ **404** حدث بسبب عاملين تقنيين معاً:
1. **عدم رفع الملفات الثنائية الكبيرة (`.apk`) بواسطة أداة Push to GitHub**:
   - أداة الرفع في AI Studio ترفع الملفات النصية فقط (ولهذا السبب يحفظ النظام ملف التوقيع الثنائي `debug.keystore` على هيئة ملف نصي `debug.keystore.base64`). لذلك لم يُرفع ملف `releases/kAM-Lite.apk` الثنائي إلى GitHub.
2. **مسار الرابط النسبي (`../../releases`) ونسخة AGP الداخلية**:
   - الرابط النسبي `../../releases` في الصفحة الرئيسية لـ GitHub يحذف اسم المستخدم واسم المستودع من عنوان المتصفح فيتحول إلى `https://github.com/releases/...` ويعطي **404** فوراً.
   - كما أن محاولة بناء الكود من الصفر داخل GitHub Actions تتعثر لأن المشروع يستخدم إصدار إضافات خاص ببيئة AI Studio (`AGP 9.1.1`) غير منشور على سيرفرات Maven الخارجية.

---

## 2. الحل الهندسي الجذري والتلقائي (The Automated Solution)

لضمان رفع ملف الـ APK الحقيقي من AI Studio إلى GitHub بنسبة 100% دون الحاجة لإعادة بنائه بـ Gradle على سيرفر GitHub، سنطبق نفس التقنية المعتمدة في `debug.keystore.base64`:

1. **تقليل حجم الـ APK**:
   - تعطيل مكتبات معاينة الواجهة غير المستخدمة وقت التشغيل (`ui-tooling` و`ui-test-manifest`) لتقليل حجم ملف الـ APK بأكثر من 60% ليكون خفيفاً وسريع التحميل على الهواتف.
2. **حفظ نسخة الـ APK كأجزاء نصية (`releases/apk_b64/part_*.b64`)**:
   - تحويل ملف `kAM-Lite.apk` المبني والموقع هنا إلى ملفات نصية صغيرة بصيغة Base64 داخل مجلد `releases/apk_b64/`.
   - لأن هذه الملفات نصية بالكامل (`UTF-8 ASCII`)، تقوم أداة **Push to GitHub** في AI Studio برفعها جميعاً إلى GitHub بدون أي استبعاد.
3. **تجميع فوري في 5 ثوانٍ عبر GitHub Actions وتحديث الروابط الكاملة تلقائياً**:
   - بمجرد عمل **Push to GitHub**، يعمل ملف `.github/workflows/release-apk.yml` تلقائياً خلال ثوانٍ معدودة ليقوم بـ:
     - دمج وفك تشفير ملفات `releases/apk_b64/part_*.b64` لإنتاج ملف `releases/kAM-Lite.apk` الأصلي والتحقق من سلامته.
     - نشر ملف `kAM-Lite.apk` رسمياً في قسم **GitHub Releases (`latest`)**.
     - قراءة اسم مستودعك الحقيقي تلقائياً (`${{ github.repository }}`) وتحديث ملف `README.md` ليحتوي على **الرابط الكامل والمباشر 100%** (بدون أي روابط نسبية `../../`) وحفظ `releases/kAM-Lite.apk` داخل المستودع.
